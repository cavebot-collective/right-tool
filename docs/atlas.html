Analysis

Soufflé

very-strongfile-clidsl

I have a work queue that propagates facts until nothing changes.

Why cross: Turns recursive fixed-point propagation into declarative Datalog and supplies optimized evaluation/indexing machinery instead of hand-maintained worklists.

Avoid when
  • Execution order and side effects are central to correctness.
  • The workload is dominated by numerical kernels rather than relations.
Closest alternatives
  • imperative worklist algorithm: Keep it when the relation set is tiny or operational ordering itself is the point.
  • general database recursive CTEs: Useful when the analysis already naturally lives inside an RDBMS and performance/expressiveness is sufficient.

Cheapest boundary: facts in / relations out, or compile to a generated executable

Data Transformation

jq

strongfile-clidsl

I need a small program just to reshape JSON in a pipeline.

Why cross: The representation matches the problem directly and crossing cost is effectively zero in pipeline-oriented JSON work.

Avoid when
  • The transformation needs substantial application state, I/O orchestration, or domain behavior.
  • The team cannot accept a separate command-line dependency.
  • Large in-memory transformations where host-language execution stays in-process and performance or richer application logic dominates; jq's declarative concision may be modest rather than dramatic.
Closest alternatives
  • host-language JSON code: Prefer when transformation is embedded in larger domain logic rather than a standalone structured-data step.

Cheapest boundary: stdin/stdout
